# Stack content refactor — implementation and QA

5 Oct 2026

Updated the app’s content outside finalized onboarding. This report covers this content change only; the checkout also contains existing work and concurrent onboarding/logo edits.

## Content source of truth

Finalized `docs/Stack content style sheet.md` and updated the supplied Downloads copy. Added the block/layer chain, the brand-verb and onboarding exceptions, copy hierarchy, loading/success/empty/error patterns, first-use personal-record education, accessibility expansion, canonical units/dates and verified product behavior. Display exercise aliases preserve stored identity and history.

Block thickness is based on distinct exercises improved against the last comparable regular-set workout: more weight at no fewer reps, or the same weight at more reps. Zero/one/two/three-or-more improved exercises select heights 1/1.15/1.3/1.45. Bonus sets and timed sets do not increase the count. More weight moved alone does not make a block thicker, and an improved workout need not be thicker than the preceding block. Weekly layers combine those block heights. The workout rating is saved; it does not adapt the next workout.

## Final glossary

| Term | Definition |
| --- | --- |
| set | One performed set within an exercise. |
| workout | One training session; also one entry in a plan or routine. |
| block | One completed workout represented in Your Stack. |
| layer | One completed training week, combining that week’s blocks. |
| Your Stack | The complete visual training object. |
| Stack | The app and brand. |
| Stack’s plan | The weekly workout sequence generated by Stack. |
| routine | A sequence the person creates, saves, imports, receives or shares. |
| training day | A calendar day with completed training; counts once toward the weekly goal. |
| PR | An earned personal record against earlier completed training. An attempt is explicitly a PR attempt. |
| moved | Weight × reps, displayed in kg, lb or tonnes for larger aggregates. |

## Intentional exceptions and preserved work

- “Give me workouts” and “What should we call you?” remain in finalized onboarding.
- “Stacked.” and “Every workout stacks up.” remain valid brand verbs.
- BW remains allowed in constrained native/card layouts. Accessibility expands abbreviations.
- First-use education may explain PR in full (“PR · Personal record”); discovery/help currently introduce it as “personal record (PR)”, with a full spoken label.
- Bulgarian Split Squat, cable stacks and weight stack retain their ordinary exercise meaning.
- User-entered names and notes remain unchanged. The simulator’s existing routine named “Split 1” remains “Split 1”; its surrounding chrome says routine.
- Legacy onboarding and onboarding-only branches retain their existing wording by explicit user instruction. Examples include “starting lineup”, “Explore without a program”, and older error contractions. They are intentional scoped exceptions, not a claim that every onboarding string already satisfies the revised sheet.
- Developer evidence/performance diagnostics retain some model terms, including internal piece/geometry vocabulary and a stored-unit `lbs` rendering in the evidence inspector. These are reached through development previews, not ordinary release screens.
- The historical app inventory is preserved as a pre-refactor reference.
